# omp-web

[English](../README.md) | [中文文档](./README.zh-CN.md) | [日本語](./README.ja.md)

Браузерный интерфейс для [oh-my-pi (omp)](https://github.com/can1357/oh-my-pi) — агента для программирования. omp-web читает сессии, которые уже записывает CLI `omp`, и предоставляет в браузере просмотр сессий, чат в реальном времени, роли моделей, настройку провайдеров, управление навыками и предпросмотр файлов проекта.

Этот репозиторий, `flowtender/omp-frond`, — форк omp-web. Интерфейс происходит от [pi-web](https://github.com/agegr/pi-web) (автор [@agegr](https://github.com/agegr)) и включает OMP-адаптации из [ddallabenetta/omp-web](https://github.com/ddallabenetta/omp-web) и [KD-MM2/omp-web](https://github.com/KD-MM2/omp-web). SDK OMP ([can1357/oh-my-pi](https://github.com/can1357/oh-my-pi)) подключён как зафиксированная точная версия пакета. Ветки и порядок обновлений описаны на английском: [docs/upstream-maintenance.md](./upstream-maintenance.md).

## Быстрый старт

omp-web обслуживает API на **Bun**, потому что SDK omp публикуется как исходники TypeScript и импортирует встроенные модули `bun:`. Требуются **Bun 1.4.4 или новее** и **Node.js 22.19.0 или новее** (см. `engines` в `package.json`; шаг `postinstall` выполняется под Node).

### Из исходников (этот форк)

Исходная копия этого репозитория и есть сборка форка:

```bash
git clone https://github.com/flowtender/omp-frond.git
cd omp-frond
bun install
bun run dev                      # сервер разработки: http://127.0.0.1:30141
```

Для продакшен-запуска из этой копии сначала выполните сборку, затем старт: `bun run build`, затем `bun run start` (слушает `127.0.0.1:30141`; `bun run start:lan` привязывается к `0.0.0.0`). Не запускайте сборку, пока `bun run dev` работает в той же копии: обе команды используют `.next/`.

### Пакет npm upstream

Пакет `omp-web` на npm публикуется из upstream-репозитория [ddallabenetta/omp-web](https://github.com/ddallabenetta/omp-web), и его `package.json` указывает на него. Это не доказывает, что форк опубликован в npm, и пакет не содержит изменений этого форка. Используйте его, только если нужен upstream-дистрибутив:

```bash
bunx omp-web@latest
```

Глобальная установка:

```bash
bun add -g omp-web    # или: npm install -g omp-web
omp-web
```

Когда сервер будет готов, CLI попытается открыть браузер; если этого не произошло, откройте [http://127.0.0.1:30141](http://127.0.0.1:30141). По умолчанию CLI слушает только `127.0.0.1`. Если провайдер модели ещё не настроен, откройте панель **Models**, войдите в учётную запись или добавьте API Key. Точка входа `omp-web` работает под Node или Bun, находит Bun и повторно запускает сервер в нём; чтобы указать конкретный Bun, задайте `OMP_WEB_BUN=/path/to/bun`.

Если в Windows `bunx` падает до запуска с ошибкой `EPERM: Operation not permitted (NtSetInformationFile())` при переносе пакета в кэш Bun, проблема в переименовании кэша Bun, а не в omp-web. Обновите Bun и повторите с очищенным кэшем.

## Основные параметры

Параметры командной строки имеют приоритет над соответствующими переменными окружения.

```bash
omp-frond --port 8080              # другой порт
omp-frond --hostname 0.0.0.0       # доступ из доверенной сети
omp-frond --no-open                # не открывать браузер автоматически
omp-frond --authenticated          # включить пароль (если его нет, спросит в терминале)
omp-frond --reset-password         # задать новый пароль, если старый утерян
```

| Параметр или переменная окружения | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--port <port>`, `-p` или `PORT` | Порт сервера | `30141` |
| `--hostname <host>`, `-H` или `OMP_WEB_HOSTNAME` | Адрес для привязки | `127.0.0.1` |
| `--no-open` или `OMP_WEB_NO_OPEN=1` | Не открывать браузер | Открывается |
| `--authenticated` или `OMP_WEB_AUTHENTICATED=1` | Включить парольную блокировку | Выключено |
| `OMP_WEB_PASSWORD` | Переопределить сохранённый пароль | Не задано |
| `OMP_WEB_ALLOWED_HOSTS` | Дополнительные точные имена хостов (прокси), через запятую | Не задано |

Встроенный HTTPS включается через `--tls-cert cert.pem --tls-key key.pem`; подробности в [HTTPS](./https.md).

## Пароль и доступ

Пароль задаётся и включается в **Settings → Access**; можно использовать и `--authenticated`, и `OMP_WEB_PASSWORD`. Пароль хранится как хэш `scrypt` в `~/.omp/agent/omp-web-auth.json` (режим `0600`). Если пароль забыт, выполните `omp-frond --reset-password` на сервере или откройте `/recover` и введите одноразовый код, который omp-frond выводит в консоль сервера.

omp-web может вызывать агента с широкими полномочиями, поэтому защищайте пароль и cookie сессии [встроенным HTTPS](./https.md), доверенным обратным прокси с HTTPS или доверенным VPN. Модель угроз описана в [authentication.md](./authentication.md).

## Роли моделей

omp назначает модель для каждой области работы. omp-web показывает те же роли, что селектор `/model` и цикл `Ctrl+P` в TUI: `default`, `smol`, `slow`, `plan`, `commit`, `task`, `advisor`, `vision`, `designer`, `tiny`.

Назначения записываются в `modelRoles` в `~/.omp/agent/config.yml` (или `.omp/config.yml`, если выбрано **This project**). Назначение, сделанное в браузере, используется и при следующем запуске сессии в терминале.

## HTTP-прокси

Серверные запросы к моделям и API используют стандартные переменные `HTTP_PROXY` и `HTTPS_PROXY`. Bun читает их один раз при запуске процесса, поэтому задайте их заранее:

```bash
HTTP_PROXY=http://127.0.0.1:7890 HTTPS_PROXY=http://127.0.0.1:7890 bunx omp-web@latest
```

Запросы к loopback-адресам через прокси не идут, поэтому локальные провайдеры (Ollama, LM Studio, llama.cpp) работают и при настроенном прокси. Учтите, что Bun пока не учитывает `NO_PROXY` для других хостов.

## Примечания

- **Каталог данных**: по умолчанию читается `~/.omp/agent/sessions`. Чтобы использовать другой каталог агента omp, задайте `PI_CODING_AGENT_DIR` (имя переменной сохранено от omp).
- **Файлы сессий**: `~/.omp/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl`.
- **Настройки провайдеров**: панель Models читает и записывает `models.yml` в каталоге агента. Учётные данные хранятся в `agent.db` omp и общие с CLI.
- **Доверие к проекту**: `.omp/extensions`, `.omp/hooks`, `.omp/tools` и `.mcp.json` не выполняются без явного решения о доверии; см. [Project trust](./project-trust.md).
- **Доступ к файлам**: просмотр и предпросмотр ограничены выбранным каталогом проекта и рабочими каталогами, которые встречаются в сессиях.
- **Git worktree**: когда появляется переключатель, как создаются и удаляются worktree, см. [Worktrees](./worktrees.md).
- **Интернационализация**: см. [Internationalization](./i18n.md).

## Возможности

- **Продолжение работы**: просмотр прошлых разговоров omp по проектам.
- **Маршрутизация по ролям**: назначение и переключение моделей для каждой области работы.
- **Безопасные ветки**: продолжение с более раннего сообщения или разделение сессии на отдельный маршрут.
- **Работа с ветками**: переключение Git worktree из боковой панели.
- **Чат рядом с проектом**: просмотр и загрузка файлов, предпросмотр исходников, Markdown, изображений, аудио и PDF.
- **Терминал рядом с чатом**: shell в выбранном каталоге из Explorer.

## Разработка

Работайте из исходной копии этого форка. Нужны Bun 1.4.4 или новее и Node.js 22.19.0 или новее.

```bash
git clone https://github.com/flowtender/omp-frond.git
cd omp-frond
bun install
bun run dev
```

Сервер разработки доступен по адресу [http://127.0.0.1:30141](http://127.0.0.1:30141). Основные проверки:

```bash
bun run typecheck
bun run lint
bun run test
```

Не запускайте `bun run build` или `next build` во время обычной разработки: они записывают данные в `.next/` и могут помешать серверу разработки. Сборку выполняйте только при подготовке релиза.

Прежде чем браться за новую функцию, прочитайте [Contributing](../CONTRIBUTING.md): там описано, в какой репозиторий отправлять изменение и какие проверки выполнить перед pull request. Про remote-репозитории, синхронизацию с upstream, порядок отправки и обновление SDK см. [docs/upstream-maintenance.md](./upstream-maintenance.md).
